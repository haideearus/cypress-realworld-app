# Monitor repair acceptance setup

Approved by the owner on 16 November 2026 for one setup PR under issue #63.
Live previews, Claude reviews, repair trials and deployment are separate later
authorizations. All three factory switches and the durable stop remain unchanged.

## Purpose and approach

Detect an existing pagination defect with a read-only production API check, then
use ordinary trusted monitor receipts, scheduled coding, fresh independent review,
protected merging and named production approval. Do not plant a broken production
commit or reclassify isolated drill evidence. The isolated rehearsal remains
separate and cannot authorize ordinary publication or merging.

First confirm the actual authenticated route against a disposable local `_test`
database. The candidate is `GET /api/transactions/public?page=1&limit=0`: the
existing helper divides by zero and serializes its page count as `null`. If the
real API does not reproduce it, reassess instead of creating artificial evidence.
Do not fix application code in this setup PR. The later coding agent must create
its own failing regression and the application repair.

## Optional check and provenance

`FACTORY_FEED_CONTRACT_CHECK_ENABLED` is absent/false by default. A new preview
input overrides it only for `dry_run=true`. No variable or secret is saved by
installation. Preserve the fixed host, existing account/session cleanup, credential
boundaries, body/request/retry bounds and eight-minute job. The extra request uses
a shorter timeout so the worst-case journey stays inside the existing budget.

The normal page-one/five-item check remains separate. The zero-size check accepts
bounded JSON 400/422 rejection or a coherent positive size of at most 50; it refuses
authentication errors, 5xx, redirects, malformed data and null/nonfinite page
metadata. Results expose a `feedContract` ok/failed enum and bounded public release SHAs,
never account/session/response data. In contract mode public health observations
bracket the signed-in journey; both must equal the later observed repair release.
Legacy reports remain observable but cannot authorize automatic retirement.

Version-two reports bind the added enum to the current run/source; legacy
version-one reports remain supported for the standard journey. Contract incidents
carry immutable `probeMode: feed-contract` in their receipt and proof. A missing or
different probe cannot recover that incident. Ordinary receipt/source checks and
legacy/drill evidence remain intact.

## Verified incident retirement

Production retirement requires a validated original bot issue and criteria,
matching ledger monitor proof, genuine same-head Claude approval and finished
review grant, a real merged PR matching its durable merge receipt, successful
main CI and the trusted exact-commit deployment run with the named owner approval,
and fresh healthy matching probes on that merge commit. No active reservation for
the issue may exist. The monitor needs Actions and pull-request read access for these proofs;
it receives no deployment, App, Claude or administration credential.

Persist a bounded retirement intent before closing the exact issue. Confirm its
closed/completed state before clearing the active pointer and recording completed
retirement. Preserve immutable issue text, receipts, grants and counters. Ambiguous
HTTP writes retain intent; a later tick revalidates the full proof before
reconciling or retrying. Failed/missing proof keeps the incident held. A manually
closed issue or spontaneous recovery alone is not proof of a deployed repair.
The existing isolated drill's explicit retirement remains separate.

Use the shared ledger job concurrency group to serialize production monitor
retirement with admission/control jobs. Preserve the publication deadline. Source
and producer identities, pagination and all lookups remain bounded.

## Verification and rollout

Test default-off behavior, valid rejection/normalization, malformed responses,
cleanup, version/mode substitution, forged criteria/provenance, stale or wrong
deployment/approval/release, active grants, lost writes, repeated observations,
legacy/drill compatibility and counter preservation. Run the factory suite,
application checks and disposable production integration; use no live endpoint or
AI provider in preparation.

After later review/install, preview the check with all agent switches false.
For a separately authorized trial, pause dependency maintenance, let the genuine
monitor create its receipt-bound issue, explicitly resume, and enable ordinary
scheduled repair. Record the PC-off interval. After terminal agent jobs, restore
the stop and false switches, approve the exact repair deployment, and let the
monitor verify recovery/retire the issue. Restore dependency maintenance only
after switches are false. Keep every usage/history record and archive evidence.

The existing limits remain 20 tickets/day, 5 coding attempts, 10 reviews, 4 retries,
one concurrent ticket, 200 turns and 30 minutes per model session. Claude Pro
OAuth is the sole AI authentication. Extra usage remains an account setting;
there is no paid API fallback or guaranteed schedule/service availability.
